04 / Power

Both cards pinned at the cap.

The 180 W limit is a deliberate choice, and it is the single largest term in the gap between measured decode and the fork's published figure.

05 / Reproduce

Bringing it back up.

The model volume is an NTFS partition that does not auto-mount. Two commands, then the server.

udisksctl mount -b /dev/nvme0n1p4     # model volume, not auto-mounted
cd ~/vllm-2080ti && ./llm.sh start    # detached vLLM server on loopback
./llm.sh status                       # server, model and GPU overview
./llm.sh bench                        # throughput benchmark
./llm.sh stop                         # stop the model, leave the workstation on

06 / Caveats

What these numbers assume.

Every figure on this page is conditional on three things: the power cap, the driver, and the context length.

01

One cap, one driver

180 W per card and driver 580.178.04. Change either and the decode figure moves; prefill barely does.

02

256K is not free

The KV cache holds 276,788 tokens, so a full 256K context runs at about 1.06× concurrency. Long context here means one request at a time.

03

One machine

These are medians from a used two-socket Xeon with SM75 cards. Useful for deciding what to run here, not for a datacentre comparison.
