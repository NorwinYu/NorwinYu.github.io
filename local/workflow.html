One machine, two audiences.

How the workstation is wired, what it actually serves on the LAN, and the path a request takes from a browser or an agent to a file in an output directory.

01 / Wiring

What is inside the box.

A 2014-era X99 board with two 22-core Xeons, two modified 22 GB cards and one NVLink bridge. Everything below is read off the workstation, not off a spec sheet.

Read it asTwo sockets, one card per socket, one bridge between the cards. The 50 GB/s link is real; the NUMA boundary above it is the part that costs context switches, not bandwidth.

88threads · 2 sockets
94GiB DDR4
44GB VRAM · 2 cards
180W cap per card

02 / On the LAN

What the network can reach.

The workstation is a generation server for the flat network, over Wi-Fi rather than the two wired NICs. Six services exist; two are running right now.

Read it asTwo audiences on one host: a human with a browser, and a program with an HTTP client. The API exists because an agent cannot drag nodes in ComfyUI.

05 / Exposure

What this is not.

It is a lab service on a home network, not a hosted product. Three consequences worth stating plainly.

01

No authentication

The UI and the API bind the LAN interface with no token. Anyone on the Wi-Fi can queue a job and read the output folder. That is the trade for zero-friction access from a phone.

02

LAN only

No port forwarding, no tunnel and no public DNS. The router's NAT is the boundary; the workstation's address is a DHCP lease.

03

One job at a time

The queue is serial and the cards are the bottleneck. This is a workstation that answers when asked, not a service with a queue you can burst.
