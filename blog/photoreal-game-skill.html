Photoreal Game Harness 不是一个 prompt 库，也不是素材包。它是一套 procedure，加八道可以拒绝你的可执行检查。

模型不会因为“再努力一点”而把 demo 变成产品；它需要一张能说不的清单。

2026 年 11 月，Saltline 用 1.4MB 的单文件证明了另一件事：模型可以写出一套内容生成器，而不只是写一个场景。问题随即变成：便宜模型能不能也做到这种“完成度”，如果给它足够的 harness？

Photoreal Game Harness 是这个问题目前的答案。它不是让模型模仿 Saltline 的模板，而是一套 procedure 加八道可执行的门，让“demo”和“游戏”的差距对模型可见。

它是什么

一句话：一个用来“做完”写实 3D 游戏的 skill。“写实”不是照片复刻，而是尺度、光照、材质、构图、运动和性能一起成立；skill 负责把这些东西变成一轮轮可检查的决策。

它不替模型写游戏。它规定模型在每个阶段必须回答什么问题：这一轮改什么？哪个 gate 最差？改完有没有变好？有没有把产品层弄坏？如果一帧变漂亮、但 loop 坏了，这一轮必须回滚。

盒子里有什么

  • SKILL.md：procedure。美术方向、光照、材质、构图、游戏 loop、产品外壳、校准，以及那些“撞过墙才留下”的规则。
  • harness/：八道 gate 和它们需要的仪器：headless render、图像统计、校准、诊断、census、collision、light audit、playtest、product、mobile、look。
  • harness/contract.md：页面契约和两套 playtest 协议。
  • site/：公开站点、case studies、harness reference 和可玩的构建。
  • examples/：三组受控运行的索引。

它是 tool-agnostic 的：harness 可选，但没有 harness，skill 就只是“愿望”；有了 harness，它才是可检查的 procedure。

八道关

表面上看是八个 PASS/FAIL，实际上每道关都在替人问一个不方便的问题：

  • shaders：页面真的能编译、能启动吗？
  • census：场景里的 mesh、实例、近景道具有没有身份？
  • collide：碰撞用的是不是玩家实际使用的那套移动代码？
  • lights：每盏灯有没有实体锚点，还是为了截图凭空加的？
  • playtest：一局能不能开始、推进、失败、重开？
  • product：标题、设置、暂停、存档、触屏、目标链和 HUD 是否完整？
  • mobile：390×844 有没有溢出，触控是不是可用？
  • look：固定机位、固定曝光下，tone 和 emptiness 是否过关？没有 reference profile 时只跑 fallback，不假装懂审美。

八道关不是“让画面更好看”的开关。它们更像一张拒绝清单：任何一道不过，这一轮就不算完成。

被失败改出来的规则

这套 skill 不是先写完再找证据，而是被几次失败改出来的。

IRONSIGHT 6/6，但游戏很薄。 第一代 skill 让它在 shader、census、collision、lights、playtest 和 look 上全绿，look 还拿到 0.87；但它只有一种敌人、一把枪，没有设置、没有存档、没有触屏，标题页还把 HUD 漏在背后。于是有了 product gate：先过产品外壳和内容宽度，再谈 look。第二代的 BLACK ICE 是 318 KB、8/8、四种敌人、Boss、6–10 分钟的一局。

提示在 3 米出现，动作在 1.8 米生效。 玩家在 2.5 米按 E，什么也没发生；UI 在撒谎，截图看不出来。playtest 现在双向检查：在范围内必须出现提示，不在范围内必须不出现；距离、文案和动作半径来自同一个常量。

Boss 死了，但局没结束。 死亡 hook 先把 boss.dead 设成 true，胜利计时器还没排上；计数器在动，结果没发生。playtest 不是读计数器，而是把 loop 打到胜利。成功和失败需要同样明确的后果。

还有雪车“爆炸”的那次：不是材质问题，是 transform stack 里每个 at() 都没有配对的 done()。只打像素分的 gate 会把碎片当成剪影；所以要有 census、collision 和可见的几何检查。

怎么用

要求很轻：Node.js 22+、Python 3.10+（Pillow）、Chrome/Chromium；没有 npm 包、没有 build step、没有 API key。

git clone https://github.com/NorwinYu/photoreal-game.git
cd photoreal-game
python3 -m pip install -r requirements.txt

./install.sh /path/to/workspace/.dsh/skills
node harness/verify.mjs --dir ../my-game --page index.html

没有 reference profile 时，look gate 跑 fallback：只检查 tone 和 emptiness，不拿别的项目风格给你打分。要真正的 look 目标，先拍 2–3 张同一项目的参考帧，校准 profile，再跑。

没有 skill loader 也没关系：把 SKILL.md 复制成 AGENTS.md，它仍然是一套 procedure。

它不是什么

它不是模板。它不保证任何模型都能做出 318 KB 的 FPS，也不保证八道关等于“好玩”。look gate 在 fallback 模式下只测 tone 和 emptiness，不是审美判断；product gate 能检查产品外壳存在，不能替你决定内容是否值得玩。

它也不是“只适用于 FPS”。城市卡丁车那组把同一个 skill 换了一个类型：通用 gate 可以复用，world contract 必须重写。这正是它作为 harness 而不是 checklist 的意义。

结论

如果只记一句：这个 skill 的核心不是“让模型更会写”，而是让模型每一轮都知道自己有没有做完。 八道关把“看起来完成了”拆成可观察的失败；失败再反过来改 procedure。
