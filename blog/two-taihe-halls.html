系统本地模型WebGL2

两座
太和殿。

同一个题目，两个时间点，两个模型：一次在本地 Maya 上跑，一次是现在线上那版。差别在取舍，不在谁更强。

一句话 prompt 就能生成一座可拖动的宫殿。真正值得看的是两次生成各自把钱花在了哪里。

十一月六日晚上，我在这台机器上让 agent 用一句中文 prompt 生成了一个明朝宫殿：单文件、原生 WebGL2、鼠标能拖着换角度。一周后的十一月十三日，同一个题目又生成了一版，现在挂在线上。

两版都能用，都只有几十 KB，都不依赖任何外部文件。但把它们并排放在一起看，能看出两个模型把钱花在了完全不同的地方——一版买氛围，一版买结构。

本地那版

它选了黄昏到清晨之间的那种光：橙色天幕、暖金屋顶、白石台基带一点点暖反，整体压暗，四角有暗角。构图不是正立面，而是带透视的斜角，左右各留了一座配殿，前景蹲着铜狮，院子铺满方砖。

界面只有两个按钮（复位视角、自转）和一行操作提示。它没有给你视角预设——它更像在做一个场景，让你自己转着看。

从会话记录看，这次生成用了 129 个步骤、15 次写入或编辑同一个文件。prompt 的原文就是一句话，还额外要求「独立完成，不参考其他文件和网络资料」。

这一版现在也在线，文件未做任何改动：ming-palace-local。可以和新版并排拖着看。

线上那版

这一版反过来：明亮的薄雾天空、居中的正立面、重檐庑殿顶的层次被强调，屋脊上的走兽、檐下的斗拱排布、匾额的位置都比本地那版更讲究。配殿被收掉，前景换成两只铜鼎，白石栏杆一段一段对齐。

界面也换了思路：右侧四个视角预设（正面、侧面、背面、俯瞰），左上角标了经纬度，底部一行「拖动环视 · 滚轮缩放 · 双击复位」。它更像一张可以转的建筑图纸，而不是一个黄昏的院子。

能数的部分

两版都是手写 WebGL2，没有 three.js 之类的库。可以直接数的差别只有这些：

  • 本地那版 41 个函数、3 次绘制调用、1 张纹理、0 个离屏缓冲；
  • 线上那版 53 个函数、5 次绘制调用、2 张纹理、1 个 framebuffer；
  • 本地 91,195 字节，线上 85,402 字节，行数几乎一样（2,333 / 2,317）。

framebuffer 那一项值得单独说：有离屏渲染，才谈得上后处理——雾、色调映射、或者把场景先画到一张贴图上再合成。线上那版的天光和空气感很可能就来自这里；本地那版把预算花在了更多几何体上（配殿、狮子、院落），只用 3 次绘制调用画完。

同等的代码量，一个买了更多模型，一个买了更好的合成。

这不是受控对比

必须说清楚：这不是 A/B 测试。

  • 模型不是同一代，一个是本地服务的 V4.1 Flash，一个是 1017；
  • prompt 只确认了本地那次的原文，线上那版在站点里只记为「一句中文 prompt」；
  • 两次相隔一周，期间工具链、脚手架和 agent 预设都可能变过；
  • 没有共同评分标准，好看与否取决于你想要哪一种。

所以能说的只有一件事：在同一个题目下，两个模型都能从一句话走到一个可交互的单文件场景，而且各自做出了可以辨认的取舍。

留下的判断

如果目标是「一张能当封面图的截图」，本地那版的氛围更划算；如果目标是「一个能讲清楚的建筑」，线上那版的视角预设和重檐细节更有用。

真正让我意外的不是质量，而是体积：两版都在 90 KB 上下，都是零素材、零依赖。模型没有把宫殿存成模型文件，它是把宫殿写成了一段程序。

方法 / 本地版来自 2026-11-06 的归档会话（provider maya，model deepseek-v4.1-flash，131,072 上下文），产物为单文件 HTML；线上版为 deepseek-flash-1017-ming-palace（仓库 2026-11-13 创建）。函数数、绘制调用、纹理与 framebuffer 数量由对两份 HTML 的静态检索得出，不是运行时 profile；截图分别是两版在 1440×900 下的首屏。
