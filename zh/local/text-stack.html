03 / 消融

MTP/2 vs MTP/3。

同一功耗上限下，每格六次运行。差异比运行之间的抖动还小 —— 这本身就是结果。

怎么读MTP/2 和 MTP/3 在这里统计上分不出来。配置留在 MTP/3，是因为没有测出来的理由去改它，不是因为它更快。

04 / 功耗

两张卡都顶在上限。

180 W 是刻意定的，它也是实测 decode 与分支公布数字之间差距里最大的一项。

注意占用率是 100%，频率却卡在上限：这是功耗预算，不是散热预算。把上限提到 250 W，decode 会涨，室温也会涨。

05 / 复现

把它重新拉起来。

模型卷是一个不会自动挂载的 NTFS 分区。两条命令，然后起服务。

udisksctl mount -b /dev/nvme0n1p4     # 模型卷，不会自动挂载
cd ~/vllm-2080ti && ./llm.sh start    # 后台 vLLM 服务，监听 :8000
./llm.sh status                       # 服务、模型和 GPU 概览
./llm.sh bench                        # 吞吐基准测试
./llm.sh stop                         # 停止模型，不关机

06 / 注意事项

这些数字的前提。

这一页每个数字都依赖三件事：功耗上限、驱动和上下文长度。

01

一个上限，一个驱动

每卡 180 W，驱动 580.178.04。改动任意一项，decode 数字就会动；prefill 几乎不动。

02

256K 不是免费的

KV cache 存 276,788 tokens，所以跑满 256K 上下文时并发约为 1.06×。这里的长上下文，意味着一次只能一个请求。

03

一台机器

这些数字来自二手双路 Xeon 配 SM75 卡。可以用来决定本机跑什么，不适合拿去和数据中心比。
