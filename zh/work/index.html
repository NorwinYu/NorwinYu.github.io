实验 / 2026

代码里的实验。

游戏是一组探针，编程工具是另一组，机器本身是第三组。它们都在问同一条真实的生产管线——生成素材、代码、UI、验证和部署——LLM 能推多远，以及人还必须在哪一步介入。

图谱

一份目录，四个变量。

这些项目不是一份游戏清单。每个项目只隔离一个变量：模型能力、围绕它的杠杆、素材管线，或者验证回路。

01

量化

把模型压到 1.6 bit 的地方版本，对 3D 场景意味着什么？明宫三维（Ming Palace 3D）就是那个量化探针。

02

杠杆

给模型一套 agent/skill 框架，和只给一个 API 循环，差在哪？NEON BREACH 是没走 harness 的对照组。

03

素材管线

程序化代码、生成图片/视频，还是 Blender 辅助？雾谷农庄是不用 Blender 的基线；Blender 版现在已经进了对比。

04

验证

Playwright、截图复查、碰撞检查，加上六道关的 harness。构建跑得起来不算结果，能被人检查才算。

每个构建背后的管线。

产出可以是一款能玩的游戏，也可以是一件能用的工具，但研究对象是管线。每个构建都跑同一条回路，只是约束不同、坏的环节不同。

01 / 游戏探针

五款游戏，五次压力测试。

能玩的产物，逼着管线同时处理状态、输入、素材、移动端布局和一个完整循环。

零号信标 ECHO ZERO / 蓝光游戏

一部未来黑色风格的视觉小说，讲记忆、信号和一座正在遗忘的城市。三条分支章节、一个画廊、一个结局回路——做成一整个叙事面，不是场景 demo。

  • 生成的场景、角色立绘、视频和中文配音；代码、UI 与声音设计由 DeepSeek Flash 完成。
  • 存档 / 读档、章节选择、画廊、设置和移动端布局。
  • 静态 GitHub Pages 构建；无后端，运行时不带 API key。

烽火三国 Beacon of the Three Kingdoms

雾谷农庄 Mistvale Farm

一款第三人称 3D 农场生活游戏，只用一句 DeepSeek Flash prompt 就搭起来：「做一款写实风的 3D 农场游戏」。开一块地、种下作物、在缓慢的昼夜循环里照料它们，把一个雾气弥漫的山谷变成家。全部在代码里生成——这是不用 Blender 的基线；Blender 辅助版现在也进了下面的对比。

  • 一句 prompt，不用 Blender，没有外部模型、贴图、字体或音频文件。
  • 程序化作物、工具、天气、水面 shader 和 WebAudio 环境声。
  • 静态 GitHub Pages 构建，本地存档，适配移动端。
  • 与下面 Blender 辅助的《拾穗》版本对比。

02 / 对比

四次受控运行。

不是每个构建都是产品。Run 01 用一台无 skill 的 3D 枪战对照一台走 harness 的 3D 枪战。Run 02 把同一个问题换到城市卡丁车。Run 03 比较同一个 checkpoint 的两种权重格式。Run 04 比较同一个农场概念在有无 Blender 下的两条资产管线。

04 / 工作负载

工作站实际在跑什么。

五类负载共享同一份 44 GB 显存预算：一个跨两张卡的 20B 视频模型、一个静图模型、一个音乐模型、一个 256K 上下文的 27B 文本模型，以及让这些数字站得住的基准。只有视频那一行需要靠探针才让第二张卡真正干活。
